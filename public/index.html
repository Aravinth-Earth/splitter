The ledger is empty

When the first expense arrives, three things happen in order:

  1. Who paid. The expense records the person who put the money down.
  2. Split how. Equally, by share, by percentage, or by exact amount.
  3. Done. Each balance moves, and the end of the trip is one short list of transfers.

What the server can and cannot see

The code is the key, and it is made in this browser. The browser turns it into an AES-256-GCM key and seals the group name and its currency before anything is sent, so the request carries a hash of the code, a hash of a secret the browser makes, and two sealed blobs.

The server holds those ids and blobs, a join mode and a revision number. It cannot read the group name or the currency, and it cannot read anything added to the ledger later. The code itself never reaches it.

Honest limits: a code that leaks cannot be revoked, a device's own cache is plaintext, and the server cannot check that a split adds up because it cannot read either number.
