Splitter

One code, one group, a shared expense list the server cannot read.

How it will work

  1. Create a group. Name it, and you are inside it with a 16-character code.
  2. Share the code. Anyone with it asks to join; you let them in.
  3. Add what you paid. Every expense lands on everyone's screen live; split it equally, by share, by percentage or by exact amount.
  4. Settle up. Balances update as you go, and the end of the trip is one short list of transfers.

What the server sees

The code is the key. It never leaves the page: the browser turns it into an AES-256-GCM key and seals every name, amount and split before anything is sent. The server holds ciphertext, ids and timestamps — and cannot decrypt any of it.

Honest limits: a code that leaks cannot be revoked, a device's own cache is plaintext, and the server cannot check that a split adds up because it cannot read either number.
